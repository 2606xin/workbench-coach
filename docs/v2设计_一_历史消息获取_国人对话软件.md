# 一、历史对话消息获取方案：国人常用对话软件

> 状态：设计稿（2026-11-11），接续 `v2设计_消息接入与文件记录.md`（企业三通道已在彼文档）。
> 本文回答：微信、QQ 这些**个人聊天软件**的历史消息，我们的底座怎么获取、明确不获取什么。

## 1. 软件全景与合规分层（2026-11 现状）

| 软件 | 官方导出 | 本地数据 | 开源工具现状 | 分层 | 底座接法 |
|---|---|---|---|---|---|
| **微信（个人）** | ❌ 无 | PC 端本地库（加密） | 生态曾繁荣（PyWxDump、WeChatMsg/留痕 等），但 **2025-10 chatlog 作者删库避险；2026-01 腾讯对一批微信聊天导出项目发 DMCA 下架**——类别性法律风险已成现实 | B（用户自担） | 只收「用户自行导出的文件」，不集成、不指名推荐任何解密工具 |
| **QQ / NTQQ** | ❌ 无 | 本地库（加密） | 社区工具同样处于灰区并受同类冲击 | B / C | 同微信 |
| 微信/QQ 实时 hook（如 DLL 注入类） | — | — | 存在但属外挂 | **C（红线）** | 永不接入：封号 + 法律风险 |
| **企业微信** | ✅ 官方 API | — | 见主 v2 文档（自建应用收件箱；会话存档付费） | A | connect 向导 |
| **钉钉** | ✅ 官方 Stream | — | 见主 v2 文档 | A | connect 向导 |
| **飞书** | ✅ 官方 API/MCP | — | 见主 v2 文档 | A | connect 向导 |
| **Telegram** | ✅ 官方导出 JSON（设置→导出） | 本地也有 | 无需工具 | A | `import` 直接吃官方导出 |
| **WhatsApp** | ✅ 逐会话官方导出 txt | — | 无需工具 | A | `import` 直接吃 |
| **iMessage / 短信（macOS）** | ❌ 无导出 | 本机 `chat.db`（需「完全磁盘访问」授权） | 有开源解析器（如 imessage-exporter） | A−（自家电脑自家乡数据） | v2.x connector：直接读本机库（用户授权后），走同一脱敏管道 |

> **分层定义**：A＝官方通道或自家本机数据，直接进底座；B＝数据在用户手里但获取手段处灰区，底座只定义「导入格式」、工具由用户自选自担；C＝红线，永不接。

## 2. 设计决策：三条红线 + 一个正式入口

**红线**（写进 README 与课堂口径）：
1. 不集成、不捆绑、不指名推荐任何「解密微信/QQ 本地数据库」的工具——这不是保守，是 2026 年已验证的现实风险（删库、DMCA）；
2. 不做任何实时 hook / 外挂式接入；
3. 个人微信/QQ 在页面上维持 v2 灰卡：显示「可通过导出文件接入，见导入指南」。

**正式入口＝统一导入格式**（后路升格为正路）：
- 已有的 `收集箱/` 和 `import` 子命令就是个人聊天软件的官方接法；
- 定义宽松的「聊天记录导出文件」规范（见 §3），任何工具、任何平台导出的 CSV / JSON / TXT / HTML 都能被吃进来；
- 导入即脱敏（复用 `Redactor`），游标按文件内最大时间推进，增量不重复。

**connect 向导只覆盖 A 层**：飞书 / 钉钉 / 企微 / Telegram / WhatsApp / iMessage。B 层永远走「文件 → 收集箱」。

## 3. 「聊天记录导出文件」格式规范（技术附录）

支持的形态（宽松解析，尽力而为）：

| 格式 | 约定 | 示例来源 |
|---|---|---|
| CSV | 列含 `时间`（可解析的日期）、`发送者`、`内容`；多余列忽略 | 各类导出工具通用 |
| JSON | 数组，对象含 `time` / `sender` / `text`（别名 `msg`/`content` 亦可） | Telegram 官方导出、自写脚本 |
| TXT | 每行一条，`时间 发送者 内容` 或 `发送者：内容`（无时间则取文件 mtime） | WhatsApp 导出、手工复制 |
| HTML | 常见导出工具的表格/气泡结构，逐行抽文本 | 留痕类工具产物 |

处理规则：去重键＝`(来源, 时间, 发送者, 内容哈希)`；每条文本过脱敏；群名/文件名作为 `project` 归组依据；`state.json` 记录每个文件的处理游标（按行号或最大时间）。

## 5. 同类开源项目盘点（2026-11 核实）

**不存在「统一提取四家历史消息」的项目**；生态分两类，与我们底座的两层一一对应：

| 类别 | 代表 | 做的事 | 与我们的关系 |
|---|---|---|---|
| 多平台消息机器人框架 | [AstrBot](https://github.com/AstrBotDevs/AstrBot)（AGPL-3.0，Python，官方支持企微/飞书/钉钉/QQ/TG 等，飞书扫码接入）、LangBot | 平台 adapter + 统一消息事件，**收新消息**、AI 回复 | 不集成（AGPL 强传染、体量大）；给「桥接配方」：其消息导出/落盘 → 收集箱 import |
| 本地库解密工具 | PyWxDump 系、wechat-extract（微信 4.x） | 进程内存匹配密钥特征（`x'<key><salt>'`）→ HMAC 校验 → SQLCipher 解密约 26 个库 → 导出 | 不集成不指名推荐；其导出产物（CSV/HTML）由 §3 导入格式承接 |
| 官方 API 直连 | lark-openapi-mcp、dingtalk-stream、企微回调 | 机器人可见范围内的消息 | `connect` 向导覆盖（主 v2 文档） |

> 个人微信在 AstrBot 官方支持列表中也无官方路径（社区走第三方协议，灰区），与我们 C 层红线的判断一致。

## 4. 给课堂的三句话

- 「微信聊天记录拿不到」是**规则问题不是技术问题**——我们只走两条路：官方通道（企业微信/飞书/钉钉），或你自己导出文件丢收集箱；
- 想导历史记录的学员：工具自选、责任自担，课程不教不荐（含法律风险提示：2026 年腾讯已对这类工具批量 DMCA）；
- 基本盘不变：拿不到的，花 1 秒复制要点进收集箱，后面全自动。
